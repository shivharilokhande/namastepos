The four questions

1. Is everything that was developed working, or are there bugs?

There were serious bugs. Five ways to keep a paid plan without paying; every auto-issued tax invoice showed ₹0 GST because order creation never wrote per-line GST; both tills recorded ₹0 GST on every order; GSTR exports 500'd; gift cards on web were unusable; two tenant-isolation holes; a guest-paid table stayed occupied forever. All fixed and deployed. Core POS/order/settle/refund path, auth, webhooks and offline sync were found solid.

2. Are all features present in admin to add to plans?

Yes. The picker reads the 52-key registry via /admin/feature-catalog; every key is grantable, grouped, with ungated keys badged. Gaps fixed: overrides, custom plans and addon grants accepted unknown keys; an empty plan inherited Enterprise's features through the pro kind/code collision; limits were unvalidated.

3. Are all features working in admin, dashboard and mobile?

Mostly, with named exceptions. Sold but delivering nothing (your call, see tracker): recurring_invoices, api_access, white_label, marketplace_addons. Fixed: recipe costing demanded the add-on on plans that include it; loyalty at mobile checkout did the same; B2B template page overwrote the receipt template (now read-only pending your decision).

4. Do features activate/deactivate per plan in dashboard and mobile?

Mobile: yes (fail-closed, X-Plan-Version on every response, 5-min backstop). Dashboard: now yes — it was a lock icon on the sidebar with every page reachable by URL and a hardcoded Starter list while loading. Server: now yes — six keys had gate rules matching no route, so un-ticking them in admin did nothing; a router-walking test now fails CI on any dead rule.
