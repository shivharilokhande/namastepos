## 1. Bugs fixed during this pass

### 1.1 KOT "Live tickets" showed completed cards under a "0 pending · 0 cooking" header
**Where:** `foodflow_dashboard/src/pages/KotPage.tsx`
**Symptom (browser-observed):** For the Kitchen station, header text read "0 pending · 0 cooking" while four green completed tickets were still rendered underneath. KDS ("Kitchen Display") for the same station correctly showed "All clear."
**Cause:** The tab rendered `stationTickets` (every ticket for the station regardless of status) while the count text only tallied `pending + in_progress`. Completed tickets belong in history, not the live board.
**Fix:** Render only `pending + in_progress` cards. Show a `· N done today` suffix in the header so operators still see finished work count, and swap the empty-state message to `✅ All clear — N tickets finished today.` when appropriate.

### 1.2 Daily closing payment breakdown misread as "count × amount"
**Where:** `foodflow_dashboard/src/pages/DailyClosingPage.tsx`
**Symptom (browser-observed):** Cash row rendered "2 × · ₹250" which reads as "2 multiplied by ₹250 = ₹500", but the actual meaning was "2 orders totalling ₹250". Cash-drawer variance shows -₹250 which is correct; the display was misleading.
**Fix:** Rewrite each row as `{count} order(s) · ₹{amount}`.

### 1.3 Admin "Businesses by plan" pie chart misclassified upgraded customers
**Where:** `foodflow_backend/src/services/adminService.js` → `metrics()` query
**Symptom (browser-observed):** Admin dashboard MRR showed ₹999 (Enterprise price), one active subscription, but the pie chart labelled it "pro". A business currently on Enterprise but with a stale row from a previous Pro trial was double-counted.
**Fix:** `SELECT p.tier, COUNT(*) … WHERE s.status IN ('active','trialing') GROUP BY p.tier` — same status filter as MRR.

### 1.4 React `Function components cannot be given refs` warning on QR code cards
**Where:** `foodflow_dashboard/src/pages/QrCodesPage.tsx`
**Symptom (console error):** Every render of the QR codes page logged the "Did you mean to use React.forwardRef?" warning because `QRCodeSVG` (pinned version) doesn't forward refs.
**Fix:** Drop `ref={svgRef}` from the SVG; PNG download already uses `wrapRef.current.querySelector('svg')` as its primary path — the ref was dead weight. Removed the unused `svgRef = useRef()`.

### 1.5 React `<div> cannot appear as a descendant of <p>` — Billing page
**Where:** `foodflow_dashboard/src/pages/BillingPage.tsx`
**Symptom (console error):** `<Badge>` (renders a `div`) placed inside `<CardDescription>` (renders a `p`) → invalid DOM.
**Fix:** Swap the `<CardDescription>` wrapper for a `<div>` styled the same way so the badge is a legal sibling.

### 1.6 Same `<div>` inside `<p>` bug in admin PlansPage
**Where:** `foodflow_admin/src/pages/PlansPage.tsx`
**Fix:** Same pattern — replace `<CardDescription>` wrapper with `<div>`, keep visual layout identical.

### 1.7 bcrypt native binding refuses to load across platforms (test blocker)
**Where:** `foodflow_backend/src/services/{authService,adminService,adminTeamService,discountApprovalService,staffService,twoFactorService}.js`
**Symptom:** `invalid ELF header` when running on Linux with a macOS-compiled binding (Jest suite fails to boot in this sandbox — user was safe on their Mac but any Linux CI/container would hit this).
**Fix:** Central shim at `src/utils/bcrypt.js` that tries native `bcrypt` first, falls back to pure-JS `bcryptjs` when the .node file's arch mismatches. Hash format is identical, so `password_hash` rows in the DB remain valid whichever library actually runs. Added `bcryptjs` to `package.json`.

### 1.8 Refresh cookie clearCookie didn't match cookie attributes
**Where:** `foodflow_backend/src/controllers/authController.js`
**Symptom:** Some browsers (Chrome, Safari) require `clearCookie` to repeat `sameSite`/`secure`/`httpOnly`/`path` verbatim, or the cookie survives logout.
**Fix:** Introduced `COOKIE_CLEAR_OPTS` with the full attribute set.

### 1.9 Missing `vite/client` types in both frontends (pre-existing tsc errors)
**Where:** `foodflow_admin/src/api/client.ts` + `foodflow_dashboard`
**Symptom:** `Property 'env' does not exist on type 'ImportMeta'` — 5 errors across the two projects.
**Fix:** Added `src/vite-env.d.ts` with `/// <reference types="vite/client" />` to both projects.

### 1.10 `ModLine[] | null` vs `ModLine[] | undefined` mismatch
**Where:** `foodflow_dashboard/src/components/NewOrderDialog.tsx`
**Fix:** Passing `undefined` (not `null`) when no modifiers chosen — matches the callee's `?:` signature.

### 1.11 `onPlaced` implicit `any` param
**Where:** `foodflow_dashboard/src/pages/GuestMenuPage.tsx`
**Fix:** Explicit `any` annotation. Doesn't tighten typing but silences strict-mode error and matches the surrounding style.

## 4. Not-a-bug — behaviour by design

- **Unknown dashboard routes redirect to `/`.** Design choice — kept, but noted for a future "proper 404" ticket.
- **Loose `== null` checks** in backend services — the widely-accepted "null-or-undefined" idiom, kept.
- **Console output in `print-agent`** — this is a CLI daemon, `console.log` is its logger by design.

No-op when `SENTRY_DSN` isn't passed via `--dart-define`.
