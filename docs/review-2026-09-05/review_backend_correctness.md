Scope: everything except entitlement/plan/billing internals. Method: read `app.js` mount order, every route file, the order/table/refund/tax-invoice/guest/auth/staff services end-to-end, migrations 079–093 vs the code that uses them, the four "recent risky changes", plus a fail-open grep and lint. ## Recent risky changes — verified

- **IRN / e-way stub honesty (`irpGateway.js`, `accountingExportService.js:97-171`, `ewayBillService.js:31-99`)** — every writer of a government-looking number goes through `irp.assertStubAllowed()` → 503 `IRP_NOT_CONFIGURED` in prod, and 501 `IRP_NOT_IMPLEMENTED` when creds are present. Three writers found (`generateIrn`, `generateEwayBill`, `ewayBillService.generate`); no other code writes `einvoice_irns`/`eway_bills`; there is no credit-note IRN path (`taxInvoiceService.cancel` writes no IRN). `tax_invoices.irn` is never populated (only surfaced). Stub values fit the columns (`irn VARCHAR(64)`, 53 chars; `eway_no VARCHAR(40)`, 33 chars). **Correct and complete.**
- **Audit durability (`auditService.js:_sendAfterAudit`)** — the audit INSERT runs in its own pool txn and the response is deferred (`writer(entry).finally(() => oldJson(body))`) until it settles; failure is logged, response still sent (documented choice). Fires only on `res.json` — every route in scope responds via `res.json`/`res.status().json`. Compatible with `idempotent()` (which wraps `res.end`, so the replayed body is stored *after* the audit row). **Correct.**
- **Test harness pool (`88c693d`)** — per-file pool registry + custom `testEnvironment.teardown()` closes every `pg.Pool`; `closePool()` idempotent on `pool.ending`; `env-defaults.js` runs in `setupFiles` so sizing applies before the first `require`. **Correct** (could not run the suite here — no Postgres in the sandbox).
- **`/v1/health` build info (`config/buildInfo.js`)** — pure, regex-validated `RENDER_GIT_COMMIT`/`GIT_COMMIT`, no I/O, spliced into both `/health` and `/v1/health`. **Correct.** (Live `curl` blocked from this sandbox — unverified against prod.)

## Migrations 079–093

- Runner (`scripts/migrate.js`) records each file in `_migrations` inside the same transaction as the DDL and serialises with an advisory lock, so a redeploy never re-runs an applied file; idempotency of individual statements is defence-in-depth only. All 15 files nonetheless use `IF NOT EXISTS` / guarded `DO $$` blocks / `ON CONFLICT`; **none would break a re-run.** No boot-time run in `server.js` (start command handles it).
- Column drift: 093 correctly realises the columns 046 "thought" it created (`eway_bills.tax_invoice_id, ewb_no, …, is_stub`) and both `eway_bills` writers now satisfy the surviving 024 `NOT NULL eway_no`. Cross-checked every `INSERT INTO (cols)` / `UPDATE … SET` in `src/` against the migration set with a script — all referenced tables/columns exist (the one drift class found is the **read** side in finding 2, `gstrExportService`, which predates 037 and was never updated).
