## Founder's four questions (admin area)

1. **Working or bugs?** The console typechecks, every API it calls exists, auth is httpOnly-cookie only, and the plan/feature editor round-trips correctly. Real bugs found: one P1 (empty/new-plan feature set silently inherits *Enterprise's* features while the console shows 0), several P2s (yearly-price toggle is a no-op, "effective features" not shown anywhere, ungated-key warning only in one of four pickers, misleading addon "Unlocks" field).
2. **Are all features present in admin as grantable?** **Yes.** The plan picker (`PlansPage.tsx:423-456`) and the custom-plan / override / addon pickers (`admin.ts:664-676 listFeatureKeys`) all read `GET /admin/feature-catalog` → `catalog` = `featureRegistry.catalog()` ∪ any stray `plan_features` key (marked `unregistered`). No hardcoded key list, no filtering, no stale names anywhere in `src/`. Verified by grepping for feature-key literals and by executing the registry (52 rows, fields `key,label,group,enforcement,why`).
3. **Are features working in admin?** Save flows work (verified payloads vs Joi schemas). Gaps are in *visibility*: no per-customer effective-feature view; ungated warning missing in 3 of 4 pickers.
4. **Activate/deactivate per plan?** Admin → `PUT /admin/tier-features/:tier` → `setTierFeatures` DELETE+INSERT in one txn + `clearAllCaches()`; correct. Caveat is F-01 below.

### Confirmed OK (no finding)

- **Feature picker reads the registry, all 52 keys, grouped in registry `GROUPS` order, unregistered keys appended visible** — `PlansPage.tsx:423-456`. `ungated`/`unregistered` badge + `why` tooltip present (`:492-512`). `client`-enforced keys are *not* distinguished (registry `catalog()` doesn't emit `clients`) — suggestion only.
- **Plan save payload round-trips**: Edit sends `{name, tier_kind, price_inr_paise, price_yearly_paise, is_active, limits}`; Create adds `tier`. Both match `createPlanBody` / `updatePlanBody` (`adminController.js:384-386, 426-445`) and `subscriptionService.updatePlan`'s column whitelist (`:294-297`). Limits are sent as the full object; `-1` preserved; rupees→paise via `Math.round(x*100)`. No key renaming/dropping. Removing a limit in the dialog removes the key → backend treats as uncapped, consistent with the "-1 = unlimited" note but silent (minor).
- **Tier code vs label**: cards show `rung.label` badge + `db tier: <code>`; kind select shows `Label (kind)`; Enterprise renders "Enterprise · db tier: pro". Good. No local tier ladder; `useTierKinds()` everywhere.
- **Overrides**: add/flip/remove call `PUT/DELETE /admin/customers/:id/feature-overrides[/:key]`; keys come from the catalog dropdown; error states don't mask a live grant (`:1050-1055`). Backend `setFeatureOverridesBody` does **not** validate `featureKey` against the registry (unlike `setTierFeatures`) — backend reviewer's item; UI cannot produce an unknown key.
- **Addons**: "Grants features" uses the catalog; sends `grantsFeatures` (camel) which `addonController._normalizeGrants` maps to `grants_features`; edit strips immutable `slug`. Slug-as-pseudo-key back-compat remains in `featureService._load:152` (documented). Backend does not validate `grants_features` against the registry either (backend item).
- **Auth/security**: no token in `localStorage` (only the `ff_admin_session` flag; legacy `ff_admin_token` is wiped on load, `client.ts:43`); no `Authorization` header; `withCredentials` cookie `ff_admin` is `httpOnly` + `SameSite=Strict` (`adminController.js:66,73`); 401 → clear + redirect, 403 surfaces as toast; login handles `requires2fa` / `mustEnrol2fa` / `authenticated`; enrol-only session is fenced server-side (`admin.routes.js:38-50`). **CSRF note**: the console's `X-CSRF-Token` interceptor (`client.ts:133-136`) is effectively dead — `ff_csrf` is set on the API host and unreadable from the admin origin, and `csrf.js:56-64` deliberately exempts `ff_admin`. Protection is SameSite=Strict + CORS allowlist, which is adequate; do not "fix" the interceptor by relaxing SameSite.
- **React state**: `CustomPlanCard` seeds once per plan identity (`seededFor` ref, `:756-774`) so background refetches don't clobber edits; dialogs unmount on close so no stale form state; `FeatureOverridesCard` flip/add compute from the last fetched array (last-writer-wins on concurrent admins, acceptable).
