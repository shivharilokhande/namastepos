# Backend review — entitlements, plans, billing (`namastepos_backend/`)

Reviewer scope: featureRegistry / featureGate / requireFeature / requireAddon / featureService / planTiers / planEntitlement / subscriptionService / customPlanService / addonService / razorpayService / dunningService / churnService / billing + addons + admin routes / `/auth/me`.
Method: read every file above end-to-end; built a route table of all 282 business-scoped route registrations (16 route files, mount prefixes from `src/app.js`) and ran each path through `featureGate.requiredFeature()` to find which FEATURE_RULES actually fire; grepped whole `src` for tier literals; ran the audit script and the drift test. No files edited.

## Founder's four questions — backend answer

1. **Working or buggy?** Core resolution (`plan_features` + overrides + addon grants + trial/grace via one `entitledSql`) is sound and cache invalidation on admin edits is complete. But the **billing lifecycle has four P0 money holes** (self-serve `resume`, addon `resume`, downgrade-to-free leaving the Razorpay mandate live, pause→resume never re-billing) and the audit's proof-of-enforcement is hollow for 6 keys.
2. **All features grantable in admin?** Yes — every registry key reaches the picker via `/admin/feature-catalog`; `PUT /tier-features` rejects unknown keys. But custom-plan extras, per-business overrides and addon `grants_features` bypass that check.
3. **All features working?** No: `recurring_invoices` has no implementation (sold on Advanced/Enterprise); `recipe_costing` as a *plan* feature is dead because `/ingredients` and stock deduction require the paid *addon*.
4. **Activate/deactivate per plan?** Server-side, removing `qr_ordering`, `whatsapp_marketing`, `captain_mode`, `multi_currency_fx`, `marketplace_addons`, `bulk_import` (menu), `bill_split` (creation) from a plan changes nothing — their FEATURE_RULES match strings do not match the routes that implement them.
