## Needs orchestrator (files I do not own)
1. **Backend `orderController.js:60` — `tax: Joi.number().min(0).default(0)`.** With `.default(0)` an omitted `tax` reaches `orderService.create` as `0`, so the new `taxOmitted = body.tax === undefined || body.tax === null` check (seen in the backend fixer's working diff) can never fire. Suggested: `tax: Joi.number().min(0),` (no default) — or `.allow(null)`. Please confirm with the backend fixer; the mobile side is coded to the "omitted = server computes" contract and until Joi stops defaulting, behaviour is identical to today (tax 0 recorded under `ORDER_TAX_ENFORCE=log`).
2. **Pre-existing, out of my item list (P1, flag for triage):** mobile order lines carry only `menuItemId/name/price/qty/note` — **no `variantId` / `modifierLines`** (`OrderItem` model + both POST bodies). Since NP-201 the server prices mapped lines from `menu_items.price` (+ variant/modifier deltas only when ids are sent), so a "Pizza Large" or "+extra cheese" line rung on the phone is re-priced to the base price server-side (and logged as a `priceAdjustments` entry); the surge `priceMultiplier` is likewise overridden by the server's menu price. This also means the mobile GST estimate can differ from the server's on variant/modifier/surge lines — the online receipt is safe (printed from the server row) but the split-leg target could be rejected. Fix belongs in `OrderItem`/`repositories.dart` bodies (+ sqflite `order_items` columns) — a larger change than this batch; not done.
