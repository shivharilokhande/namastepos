# Dev Loop and Gates

Local Postgres runs on the Mac (`pg_isready -h 127.0.0.1`). Test DB: `postgresql://namastepos:namastepos@localhost:5432/namastepos_test`.

```bash
# backend — ALWAYS capture the exit code to a file; `| tail` returns tail's status
cd namastepos_backend
DATABASE_URL=postgresql://namastepos:namastepos@localhost:5432/namastepos_test NODE_ENV=test \
  npx jest --runInBand --silent > /tmp/t.log 2>&1; echo EXIT=$?; grep -E "^(FAIL|Tests:)" /tmp/t.log
npx eslint src tests            # 0 errors; ~200 warnings are baseline, do not "fix"
node scripts/feature-registry-audit.js   # must print OK

cd ../namastepos_dashboard && npx tsc --noEmit -p . && npm run lint && npm run build
cd ../namastepos_admin && npx tsc --noEmit -p .        # no eslint config yet
cd ../namastepos_flutter && flutter analyze && flutter test
```
Baselines 2026-09-06: backend 943/943, Flutter 131/131, all lint 0 errors.

Tests create unique businesses per run; `resetDb()` in a few suites drops the schema — **don't run two jest processes on the same DB at once.**

## CI (`.github/workflows/ci.yml`)
Jobs: backend, dashboard (tsc + lint + build), admin, mobile, mobile-next (advisory), marketing-claims-live, Cloudflare Pages ×3. No branch protection; repo is **public**. CI signs release APKs with a throwaway key — real releases are built locally with `android/key.properties`.

**The red ✗ that is not a failure:** `marketing-claims-live` is `continue-on-error`; GitHub paints a red cross on the commit while the run is green. Check `gh api repos/:owner/:repo/commits/<sha>/check-runs`, not `gh run list`. When it is red it usually means plans were edited in super-admin and `tests/fixtures/plan-feed.json` must be re-pinned in the same commit as any copy change.

`graphify-out/` is gitignored and regenerated by a commit hook — ignore it.
